\# Formato de Reporte de Incidencias

\## Proyecto ITLA TaskFlow



\### 1. Objetivo

Establecer un formato estándar para documentar los errores o problemas encontrados durante las pruebas de calidad (QA) del sistema ITLA TaskFlow.



\### 2. Datos de la incidencia



| Campo | Descripción |

|---|---|

| ID de incidencia | Código único para identificar el problema |

| Título | Nombre breve del error |

| Fecha | Día en que se detectó |

| Módulo | Parte del sistema donde ocurre |

| Prioridad | Baja, Media, Alta o Crítica |

| Estado | Abierta, En proceso, Corregida o Cerrada |

| Responsable | Persona encargada de revisar la incidencia |



\### 3. Descripción del problema



\*\*Descripción:\*\*  

Explicar claramente el error encontrado y las condiciones en las que ocurre.



\*\*Pasos para reproducirlo:\*\*

1\. Ingresar al sistema.

2\. Acceder al módulo correspondiente.

3\. Realizar la acción que provoca el problema.

4\. Observar el resultado.



\### 4. Resultado esperado

Describir qué debería suceder cuando se realiza la acción correctamente.



\### 5. Resultado obtenido

Describir qué sucedió realmente durante la prueba.



\### 6. Evidencias

Adjuntar capturas de pantalla, mensajes de error o registros que permitan analizar el problema.



\### 7. Seguimiento

Registrar las acciones realizadas para solucionar la incidencia y verificar que haya sido corregida.



\### 8. Criterios de cierre

Una incidencia puede cerrarse cuando:

\- El problema ha sido corregido.

\- Se ha repetido la prueba correspondiente.

\- El resultado obtenido coincide con el resultado esperado.

\- Se ha documentado la solución.



\### 9. Observaciones

Este formato permite mantener un registro organizado de los problemas detectados durante las pruebas de ITLA TaskFlow. No representa incidencias reales; es una plantilla para documentarlas cuando sean encontradas.
